## Retry a failed post + database-backed tests

- **New endpoint `POST /posts/{id}/retry`** and a **Try again** button in
  Post Studio. Safety rules (the "never double-post" promise):
  definite failures retry in one click; jobs with an unknown outcome
  (`needs_review`) only after the user confirms "I checked — it isn't on
  the page"; jobs that already posted are never resent; the content must
  still match what was approved; a disconnected account must be
  reconnected first. The same job rows are re-queued so the post ends up
  "Published" correctly; the earlier error stays in the audit log.
- **Related fix:** editing a *failed* post used to leave it stuck as
  "failed" with no way to resubmit. It now goes back to draft (needs
  approval again), like an approved post does.
- **Started the database-backed test suite** (`backend/tests/integration/`):
  creates a fresh `ai_content_test` database with the real migrations,
  calls the real API, runs the worker task in-process. Skips itself if
  PostgreSQL isn't running. 7 tests: publish-now end to end + 6 retry
  safety cases (reconnect then retry, never resend completed, unknown
  outcome needs confirmation, content changed after approval, failed-post
  edit, wrong status + other workspace → 404). Total suite: **59 passed**.
- **Bug found by the new tests:** two people with the same name signing up
  in the same second got a 409 (workspace address = name + timestamp).
  Fixed with a random suffix; the duplicated code now lives in one place.
- Verified in the browser: the seeded failed post "Yoga timings update" →
  Try again → page updated itself to Published, account "Posted".
