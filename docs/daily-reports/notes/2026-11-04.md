## Non-code work

- **Full backend review** before starting the frontend. Read all ~5,000 lines,
  ran the 27 existing tests (all passed, but none touched the database or API
  routes), then reproduced each suspected bug against a throwaway database.
  Found 8 bugs + 4 smaller issues. The 4 most serious:
  1. Hashtags/CTA could be edited after approval without re-approval.
  2. A post could be changed while waiting for approval, and the approver
     would approve the new version without knowing.
  3. "Publish now" never published immediately (wrong task arguments, error
     silently swallowed; only the once-a-minute scheduler picked it up).
  4. Bad input (long `X-Forwarded-For` header, `null` caption, 300-char
     title) caused server errors (500) instead of clear messages.
  All fixed in commit e3e7112 (see its message for the full list).
- **Hidden bug found while verifying the fixes:** Celery tasks were attached
  to the wrong Celery app, so *any* dispatch from the API went to a broker
  that doesn't exist (RabbitMQ default port 5672). Also `kombu` had drifted to
  a version incompatible with our `redis` client. Fixed + pinned in e3e7112.
  Verified end-to-end with a real Celery worker: publish-now → both mock jobs
  completed → post marked published.

## Decisions made today (by us)

- AI is deferred to Phase 2 (instruction from the developer, per owner direction).
- `allow_self_approval` defaults to ON so a one-person business can complete the
  owner's journey alone (owner's journey step 4: "the user submits … and explicitly
  approves"). Agencies switch it off. This was decision D1 in the plan; we built
  the recommended option — confirm with the owner.

- **Self-approval made automatic** (after the daily report flagged that the
  plan said "off once a second member joins" but the code only had a manual
  owner switch). Now: ON for a new one-person workspace; switched OFF
  automatically when the second member is added (only on the 1 → 2 change,
  recorded in the audit log); the owner can still turn it back on, and later
  invites don't undo that. Demo seed workspace (2 members) starts with it OFF.
  D1 question to the owner is now "confirm this rule", not "pick an option".
